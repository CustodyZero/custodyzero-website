## A page. A margin. The keys.

Type is built around the act of typing, not around the surface that surrounds it. The pencil margin on the left isn't decoration — it's where the paper would feed if Type were a typewriter. The Margin and Line — the icon at the top of this page — is the same idea: a margin, and a single line of text. Pre-tech typing had purity because there was nothing competing for the writer's attention. Type carries that purity into a modern tool.

The page is the page. The font is yours — pick what fits. Four themes — Light, Desk Lamp, Warm Inversion, Late Evening — pick the one that gets out of your way. What stays is the writing.

No markdown syntax appearing as you type. No preview toggle to see what your work will look like. No panels that have to stay open because the only way to reach a command is to click one.

## The keyboard is the spine

Every command Type can do is reachable from the keyboard. That isn't an accessibility feature added on top — it's the design from the start. The page can stay clean because nothing on it requires a visible panel; every action has a key.

**⌘K — the spotlight.** A searchable command palette. Type "format" — every formatting command surfaces. Type "doc" — navigation. Return runs. Escape dismisses. Every command Type can do is reachable from here.

**Format in place.** ⌘B for bold. ⌘I for italic. ⌘U for underline. ⌘⌥M, then type LaTeX, Return — math renders in the line. No `**bold**` ever appearing on the page. What you see is what's there.

**Style-stack peel-back.** Bold, then italic, then a heading — applied as a stack. Want just the heading off? Escape pops the last applied style. Mouse not involved.

In every Type demonstration on this site, the cursor is not visible. Keyboard-first isn't a feature on a list. It's the posture the whole product is built on.

## Your editor, your companion

Type's Assist learns your voice. Each project keeps its own voice file — a captured sense of how you write — so when Assist suggests, the suggestions sound like you, not like generic output.

Three ways Assist works:

- **Advisory** — margin notes. Observations you can take or leave.
- **Proposed** — suggested edits in the text. Accept or reject by keyboard.
- **Direct** — when you ask: rewrite this paragraph, continue from here, expand this point, summarize the section.

When Assist contributes text to the page, that text is rendered in a different ink — *assist*, a muted blue — so you can see what came from Assist and what's yours. Authorship stays with you because you can see it, plainly.

The assist runs on your machine. Nothing leaves the page.

## What's in Type

- **Assist** — three modes. Advisory (margin notes), Proposed (tracked suggestions you accept or reject by keyboard), Direct (rewrite, continue, expand, summarize). All keyboard-driven.
- **Semantic search** — across your project. Offline. Scoped to your work, not the world.
- **Per-project voice file** — Type captures how you write, project by project, so the suggestions sound like you.
- **Full rich text** — lists, ordered lists, images, inline math, display math. Not prose-only.
- **Four themes** — Light, Desk Lamp, Warm Inversion, Late Evening.

## What Type is not

- **Not a Markdown editor.** The page is the page; you don't write `**bold**` and toggle to a preview.
- **Not a business tool.** No version-control panel. No team collaboration sidebar. No project-management graft.
- **Not a code editor.** The shortcuts are borrowed from that world; the writing isn't.
